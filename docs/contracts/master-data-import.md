# 主資料匯入 XLSX 契約 v1

此格式是「專案檔與備份」頁下載的獨立編輯範本，與完整工作區備份、活動交接檔及舊版 66 張工作表契約互不相同。格式識別為 `ConMate主資料匯入`，格式版本為 `1`；不隨應用程式版本或完整專案 XLSX 版本變更。

## 工作表

| 工作表 | 欄位 | 用途 |
| --- | --- | --- |
| `00_匯入說明` | 項目、內容 | 格式、版本、工作區 ID、基準修訂與限制 |
| `01_參與方` | 資料ID、新增代號、名稱、備註 | 新增或更新參與方 |
| `02_企劃` | 資料ID、新增代號、名稱、說明 | 新增或更新企劃 |
| `03_商品` | 資料ID、新增代號、商品名稱、商品擁有者ID、創作者ID、企劃ID、周邊種類、規格、柄圖名稱、柄圖ID、備註、標記ID（以、分隔） | 新增或更新商品 |
| `04_場次` | 資料ID、新增代號、場次名稱、開始日期、結束日期、地點、備註、參加企劃ID（以、分隔）、狀態 | 新增或更新場次及參場企劃關聯 |
| `05_柄圖` | 資料ID、新增代號、柄圖名稱、企劃ID、作者ID（以、分隔）、備註、狀態 | 新增或更新柄圖與作者關聯 |
| `06_標記` | 資料ID、新增代號、名稱、狀態 | 新增或更新標記 |
| `07_自訂欄位` | 資料ID、新增代號、欄位名稱、欄位類型、狀態 | 新增或更新自訂欄位定義 |
| `08_欄位選項` | 欄位ID、欄位新增代號、選項ID、選項新增代號、選項名稱、狀態 | 新增、改名或封存／恢復單選及多選欄位的選項 |

欄名必須符合契約；欄位順序可以調整。不得加入非空白的額外工作表或未命名欄位。所有儲存格須為純文字或空白，不支援公式。

## 識別及參照

- 既有資料列保留原 `資料ID`；匯入以 ID 精確更新，不按名稱、列號或順序猜配。
- 新資料列的 `資料ID` 留白並填該表唯一 `新增代號`。代號為 1 至 60 個 ASCII 英數字、句點、底線或連字號，不區分大小寫。
- 參與方、企劃、場次、柄圖、標記、自訂欄位及商品各使用自己的 ID／新增代號命名空間。參照既有紀錄填 ID；參照同檔新增紀錄填 `new:新增代號`。
- 商品標記 ID、場次參加企劃 ID、柄圖作者 ID 以全形頓號 `、` 分隔；作者只能指向參與方，參場只能指向企劃。
- 商品與場次可使用同檔新增的企劃／參與方；商品可用 `new:新增代號` 指向同檔新增的柄圖及標記。
- 柄圖企劃可留白；有填寫時必須是明確有效的企劃參照，商品選用的柄圖須與商品企劃一致。商品周邊種類以名稱輸入，相同名稱沿用既有種類，否則依既有建檔規則新增。規格亦依商品建檔規則建立或沿用。
- 欄位選項使用 `欄位ID` 或 `欄位新增代號` 指向自訂欄位。既有選項保留 `選項ID`；新選項留白 ID 並填新增代號。每一欄位內代號唯一。
- 欄位類型固定為 `text`、`number`、`single`、`multi`、`boolean`、`date`。只有 `single`／`multi` 可以有選項；每個此類欄位至少要有一個使用中選項。

## 封存及不可變更

- 不支援以刪列刪除任何既有資料；每一張可編輯表都必須保留該類型全部既有 ID。
- 場次、柄圖、標記及自訂欄位既有資料列的 `狀態` 必須與目前工作區一致，匯入不變更這些紀錄的封存狀態；新增資料列的狀態必須為「使用中」。封存中的場次、柄圖、標記及自訂欄位不可編輯；請在網站先恢復。
- 既有自訂欄位類型不可變更。既有選項 ID 必須全部保留；可將選項狀態改成「已封存」而非刪除，選項 ID／標籤不會被套用到既有商品自訂值上重新計算。
- 若場次已被交易使用，匯入不得修改場次內容或參場企劃，避免變動歷史交易顯示脈絡。
- 匯入不修改商品既有自訂欄位值或商品封存狀態；新增商品的自訂欄位值為空。商品、企劃與參與方的穩定 ID 不變。

## 驗證與提交

- 範本須來自目前選取的工作區，且基準修訂必須與本機相同；不同工作區或過期檔案拒絕提交。
- 檢查重複／未知 ID、重複新增代號、缺少既有列、欄位型別、選項、狀態、日期、外鍵及多對多參照。
- 檢查通過後，先顯示新增／更新差異；錯誤提供結構化 JSON 報告。只有使用者確認後才於單一資料庫交易提交，提交時再次檢查修訂。任何錯誤都會拒絕整份匯入，不提交部分資料。
- 庫存、單件、販售、退款、成本、代墊、費用、分配及結算不在可編輯範圍，且會由匯入流程完整保護。完整專案備份與活動交接檔的還原流程不變。
- XLSX 在本機以 Web Worker 檢查與解析，不上傳。沿用安全檢查：檔案最大 10 MB、展開後最大 30 MB，拒絕公式、外部關聯、巨集及嵌入附件。
