# Excel 1.0.0 格式契約

本文件與 workbook.json 是待實作的格式規格；尚未產生 XLSX 模板或匯入器。

## 工作表與欄位

完整字典見 [workbook.json](workbook.json)：66 張表、固定中文欄名、內部 key、型別、必填、可編輯、參照目標及選項集。欄位順序可變，依完整欄名讀取；缺必要欄、重複欄名、非空未知欄報錯。新增空白欄警告。未知非空工作表拒絕，未知空白表警告，避免備份默默丟資料。

全部工作表都存在且可見；空白表只有表頭。工作表名稱不可改；第一張必須是 `00_使用說明`。說明表不是業務資料，但公式與安全掃描仍包含它。資料區不得合併儲存格。

| 編號 | 內容 |
| --- | --- |
| 00–10 | 使用說明、格式、工作區、參與方、企劃、場次、通路及販售作業 |
| 11–21 | 商品、規格、柄圖、權益、製作及單件 |
| 22–29 | 費用、分攤、付款與出資 |
| 30–39 | 方案、池配置、後續號碼資料及抽選結果 |
| 40–49 | 庫位、異動來源、交易、實際商品、收款、更正與退貨 |
| 50–56 | 結算規則、適用款式、參與方、結算抵付及結案處置 |
| **57–58** | **人工分配決定、人工分配項目** |
| **59–61** | **盤點單、盤點明細、盤差處理** |
| 90–92 | 系統關聯、計算結果及匯入修訂歷史 |
| 99 | 固定選項字典 |

人工分配項金額允許正負，以「此參與方應取得」為正、「應繳回」為負；相反方向須明確顯示，不讓使用者猜符號。系統計算的負值與各方損失分配也保留明確方向。

`46_出庫批次指定` 是輸入要求；實際結果 StockIssueAllocation 在系統關聯紀錄，不能把結果與要求同時各扣一次。DrawResult 與 SaleFulfillment 的雙向參照如同時存在，必須互相一致；不得因迴圈而按表格順序匯入。

## 型別及編輯規則

- text：實際文字儲存格，保留 `007`；不是看起來像文字的數值。備註可換行。
- uuid：既有不可變；新增留白；未知自填 ID 不視為新資料。
- reference：`new:代號` 或 `code:顯示編號`；不能使用儲存格位置或名稱猜配。
- money：非負整數數值；signedMoney 可負；不得含 NT$、單位或字串數字。
- unitMoney：非負數值，最多四位小數；內部轉定點數，不直接浮點算錢。
- percent：0–100 數值，最多四位；20 表示20%，百分比格式的0.2不可默認當20。
- quantity：安全非負整數；售出、調撥、抵付等有效動作須大於零。
- date：純文字有效日曆日期 YYYY-MM-DD；序號日期不猜測。
- datetime：純文字 ISO 8601 含時區；範例 `2026-11-02T14:30:00+08:00`。
- booleanText：實際文字 `TRUE` 或 `FALSE`；不收原生布林或0／1。
- 空白不是0、FALSE或空日期。required=false 仍可能條件必填。

灰色系統欄、淡藍可填必填欄、淡黃選填／注意欄；以名稱、註解及說明補充，不只靠顏色。所有表凍結表頭、提供篩選、無資料區合併。下拉選單不代表已通過驗證；不加密碼鎖定阻礙相容軟體。

通用操作不代表每表都接受全部操作：版本使用後不可改寫；已提交來源需更正；derived/system/computed不可新增任意列。mixed 依來源是否為系統產生決定欄位鎖定，未能確認來源時報錯，不能信任使用者自行宣稱。

P0 仍匯出完整結構及全部啟用資料；不支援的業務列只能原樣還原，不能執行未完成的編輯命令。若無法無損還原則阻止而非丟棄。檔案種類不是安全證明，不信任可被改寫的metadata。

## ID 分配

1. 一次讀全部表，檢查正式ID、編號、修訂及暫時代號。
2. 暫時代號 trim；ASCII 大小寫不區分，正規化差異警告；同實體本檔內唯一。
3. 在暫存預配所有新 UUID 與顯示號，不寫正式序號。
4. 解析所有參照，包含向後與雙向參照。
5. 比對目標工作區、來源修訂及來源紀錄；既有ID不能換實體。
6. 預覽通過且確認後原子提交序號、資料及ImportReceipt。
7. 輸出帶正式ID的新檔；相同文件再次新增拒絕，使用新檔繼續編輯。

需要參照尚未生成的出庫、試算或結算系統ID時，分兩次操作：先匯入來源、下載結果，再新增其退款或付款抵付。不能替不存在的系統結果自編ID。

## 條件及合計驗證

- 費用分配目標類型對應柄圖／批次／共通項目，恰填一種。
- 確定費用要有實際金額；分配額合計等於該費用採用金額。
- 資金抵付必須有真實來源；可償還本金不得超實付歸屬；付款用途合計不超付款。
- 柄圖群組明列品項及數量；權重和須正、除數不可為零。
- 商品權益合計100%；不當作分潤或虧損負擔。
- SKU種類與規格匹配，柄圖／製作／方案的企劃關係一致。
- 販售作業允許相關企劃；共用池配置不與可用量相加，專用保留不能超庫存。
- 預覽整份變更後的庫存與交易，不能只逐列驗證。
- 單件必須對應正確批次與唯一位置；單件出入數量為1。
- 退款連回實際出庫，累計退貨／退款不可超原來源允許量。
- 系統分配、人工分配付款抵付恰選一個目標。
- 盤點空實點數為尚未點，不當0；庫位／批次一致；更正截止前來源則needsReview。
- financial rule 缺少必要口徑列unknown，不使其他合法交易或人工結案失效。
- 未解盤差、未付或人工分款不平衡是警告；總額差異明列保留／不足，不偽造配平。

結算規則的「扣製作成本／扣柄圖成本」明填TRUE或FALSE，空白表示未知，不視為FALSE。扣指定成本時被選為TRUE的成本基礎必填。「明確覆寫規則」指向被取代版本，不能成環；只對相同來源及明確適用範圍生效，不能改先前成交快照。

「償還順序」只接受固定token以半形 `>` 連接：`柄圖回收`、`製作代墊`、`管理費`、`抽成`，例如 `柄圖回收>製作代墊>管理費>抽成`。不得重複token；只包含實際啟用步驟。此順序僅處理款項抵付，抽成基礎仍由規則版本明確指定，不以字串順序暗中改變利潤公式。空白不自動抵付。更複雜的通用多筆瀑布規則延後P1另擴版，不把自由文字當程式執行。

## 系統資料與重算

`90_系統關聯紀錄` 依 recordType 驗證固定版本結構與所有ID。typedJson不是任意JSON儲物箱：只接受字典列出的實體及欄位，BigInt以十進位字串，不能含可執行內容。空白模板無系統紀錄。

系統資料修改與一般原始資料修改分開：

- 原始資料合法更改：以更正命令重建衍生影響，預覽。
- 只有91計算值不同：警告並忽略該值，採重算結果。
- 原始資料不變但相同規則重算不一致：阻止，表示完整性問題。
- 原ID、系統分錄或已確認快照被改：更新模式拒絕，要求修改來源。
- 乾淨裝置還原沒有可信基準，只能做內部一致性驗證；不宣稱能辨識所有竄改。

## 安全與相容

解析前檢查檔案大小及ZIP目錄；拒絕路徑穿越、重複項目、加密檔、異常壓縮比、過量項目或解壓總量。限制需在T11實測後固定，不使用無上限解壓。

檢查OOXML relationships/content types；拒絕巨集、OLE、查詢／連線、外部關聯及不支援嵌入內容。所有表、隱藏儲存格、shared／array formulas均掃描。XML禁止DTD與外部實體。ExcelJS正常讀取不是安全驗證成功。

以明確字串型別保存以 `= + - @` 起始的文字，不執行、刪除前綴或用HTML渲染。輸入的安全文字不因像公式就毀損；實際OOXML公式節點則一律拒絕。錯誤報告亦適用同規則。

Excel／LibreOffice必測；其他軟體按型別契約檢查，不承諾所有重存轉換。保留不了前導零或將日期轉序號時給具體修正，不猜原值。

## 升級與完整往返

格式版1.0.0；破壞欄位或語義的變更升major，支援舊版在暫存遷移。未知新版拒絕並提示更新，不清除原資料。可選新增欄位也需明確升版，不靠忽略未知非空欄偷渡。

完整往返比較正規化原始資料、ID、關聯、規則版本、歷史、存貨及重算。排除樣式、文件ID、匯出時間、新增匯入事件。排序與XLSX二進位差異不代表資料不同。
