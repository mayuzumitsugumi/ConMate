# 第一版驗收與正式發布

本文件區分自動驗證與真實裝置驗收。v0.29 是第一版驗收候選版；功能部署到 Pages 不等於已通過使用者實機驗收，也不直接標為 v1.0。

## 候選版範圍

- 創作管理：多企劃／活動、創作者／柄圖、商品、自訂標記／欄位、批次與庫存、成本／代墊／人工分配、營運報表、寄賣及預售。
- 活動工作台：限定範圍交接、逐筆實際販售、退款／換購、無料／損耗、全品項盤點、唯讀結案、冪等合回、實物退回確認。
- 資料安全：IndexedDB 原子提交、操作重送與修訂檢查、本機復原點、完整 XLSX 備份、活動檔、精簡主資料匯入。
- 效率：商品圖片與條碼輸入、商品備註批次修改；數量、成本、款項仍由各自業務命令處理。

### 不阻擋第一版的延後項目

Google／Microsoft OAuth、即時多人同步、自動雲端備份、平台 API、相機掃碼與標籤列印、進階促銷、正式會計帳、多幣別、跨多次入庫的成本自動分攤、活動或寄賣端代交預售、店家批次回報匯入。

GitHub 個人權杖手動備份是選配；尚未使用私人帳號驗證，不能稱為 OAuth 登入。不可要求使用者提供權杖至對話或 issue。

## 發布前自動檢查

在同一個候選提交執行並保存結果：

```sh
python -m unittest discover -s tests -p '*_checks.py' -v
npm test
npm run build
npm run test:e2e
```

若使用系統 Chromium，最後一項可加 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`。GitHub Actions 必須通過 check-build 與 Pages deploy；檢查 /ConMate/ base、manifest、Service Worker 和 Hash 路由。不得以取消檢查來發布。

檔案容量限制為壓縮10 MiB、展開30 MiB；超限時匯出拒絕下載，不可當作已有外部備份。自動容量案例可還原500商品／20創作者／1,000筆交易；10,000筆案例報表通過但Excel展開超限，不能宣稱可完整備份。這不是商品或交易筆數硬上限，圖片與內容長度也影響容量。

必要回歸：舊檔遷移／新檔往返、活動資料範圍、冪等合回、預留／FIFO／單件守恆、退款與現金分離、未計算規則保留未知、斷網重新開啟、失敗不留下半筆。圖片與條碼不得變成自動成交入口。

## 交給使用者的實機清單

請使用「驗收練習」獨立工作區及虛構資料；先匯出正式資料備份。不要清除網站資料來更新。

| 情境             | 裝置／環境                                       | 通過條件                                                                                                 |
| ---------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| 更新與資料保留   | 原使用的桌面 Chrome                              | 先保存草稿、接受更新、重新開啟，原商品與交易仍在；兩個入口可切換，桌面按鈕不斷字。                       |
| 安裝與離線       | Android Chrome、iPhone／iPad Safari 與主畫面模式 | 連線確認離線資源準備完成後，斷網重新開啟；可新增商品、成交、盤點與下載備份。                             |
| 手機操作         | 真實手機、直橫向                                 | 表單、商品卡、收款與確認框可用；沒有必要按鈕被鍵盤遮住；不誤觸重複成交。                                 |
| 圖片             | 實際手機相片                                     | 合法圖片可轉縮圖並離線顯示；過大或不支援檔案有說明；移除圖片不影響商品及庫存。                           |
| 條碼             | 實際掃碼槍或手動輸入                             | 前導零保留，Enter 僅查找／選品，不成交；重複或未知碼不錯選商品。相機掃碼不在本版。                       |
| 大量編輯         | 桌面、手機                                       | 先選商品、核對預覽再提交；未選商品不變；既有成交快照不被改寫；過期預覽須重做。                           |
| 完整備份         | 另一台乾淨裝置／瀏覽器                           | 匯出後還原，ID、圖片、條碼、交易、帳務及庫存一致；另一端原工作區不被無提示覆蓋。                         |
| 試算表相容       | 使用者實際 Excel／LibreOffice                    | 完整備份重存可驗證還原；主資料範本新增／修改有預覽；公式／錯誤參照報錯。日常閱讀表不是任意編輯還原入口。 |
| 活動交接         | 兩台裝置、兩份交接                               | 僅交付範圍資料可見；離線販售、全品項盤點、差異待查結案；逐份合回，重匯不重扣庫，實物另確認退回。         |
| 寄賣／預售       | 練習工作區                                       | 寄賣交付不算營收；預售收款不自動扣庫，交付不重複收款；退款與庫存處置分開。                               |
| 選配 GitHub 備份 | 使用者自己的專用私有庫                           | 先用虛構資料驗證上傳與還原；權杖不寫入備份，遠端已變更時阻止覆寫。不使用者可略過此選配。                 |

Playwright 手機 viewport 或 WebKit 不等於真實 iOS 驗收。尚未測試的裝置／試算表版本請明列，不填「通過」。瀏覽器清除網站資料、私人模式、系統回收空間及裝置損壞仍可能遺失本機資料；需另存外部備份。

## v1.0 發布門檻與流程

1. 自動檢查全部通過，候選版 commit 與部署一致。
2. 使用者完成自己主要裝置的離線、販售、備份還原及交接演練；未涵蓋平台明列限制。
3. 阻塞的資料遺失、重複扣庫、帳務重複及敏感資料外洩問題修正後，相關回歸重跑。
4. 使用者確認正式發布後，再建立 v1.0 版本、正式 release note／tag 並部署；不重置使用者資料、不重新產生既有 ID。
5. 保留原候選版及故障前備份；遇到新版格式不可讓舊版程式強行降級。Git 回退程式並不等於資料庫可以降級。
