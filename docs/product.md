# 產品決策與交付順序

狀態：T01 規格基線，2026-11-02（Asia/Taipei）。後來確認的決策優先於早期提案。此文件不是完成整個 MVP 的宣告。

最新修訂以[網站優先決策](decisions/website-first.md)與[個人雲端備份規劃](decisions/personal-cloud-backup.md)為準：網站先建檔，單檔匯出；使用者自己的私有GitHub repository備份已提供個人權杖手動連接、備份與還原；尚非 OAuth 登入。下方T01任務狀態保留原基線，實際已交付功能見各版本說明。

目前缺口與實作順序見[現況與路線圖](implementation-roadmap.md)。

## 分批交付

### P0：目前企劃最小完整流程

1. 多名創作者、商品種類／規格、柄圖與 SKU、批次、兩個場次及庫位。
2. 現表單件印製成本加權分攤；實付成本、約定回收額及差額並列。
3. 自付／總召投入、扣柄圖後抽成／扣指定成本後抽成；不能把未知規則當成零。
4. 徽章＋吊飾混池、拍立得池、指定立牌、同款隨機與指定不同價。
5. 逐筆實際選品、收款找零、原子成交、取消／退款、錯款更正。
6. 跨場調撥、第二場調價、盤點與未解差異。
7. 手機可操作、離線、重新開啟、完整 XLSX 備份還原；基本建檔模板與檢查。

基本備份必須包含所有已啟用資料，不可用簡化報表冒充。首批建檔模板只開放 P0 可驗證的資料操作；未支援的外部修改明確拒絕，不靜默丟棄。

### P1：通用 MVP 補齊

全工作表外部往返編輯、其他柄圖分攤方式、特殊單件操作、專用池保留、通用固定管理費與自訂先後、完整錯誤報告、擴充報表。契約欄位在 P0 先固定，但不將尚未完成的介面標為可用。

### P2／未來

實體號碼與輪次操作、系統抽獎、圖片條碼、完整寄賣、預售、套組促銷、多幣別。分支合併及即時同步要重新評估架構；無帳號不提供防竄改／權限承諾。

### 備份擴充：已確認的個人GitHub雲端備份

排在本機匯入還原可驗證之後，不延誤當前企劃的急用功能。C01本機還原 → C02安全授權可行性 → C03手動備份 → C04雲端還原／版本 → C05便利性擴充。C02可與C01並行研究。使用者選自己的私有repository，一工作區一檔案；依遠端SHA防止覆蓋衝突，不做即時同步。授權技術、任務完成條件及12項驗收見[完整規劃](decisions/personal-cloud-backup.md)。

## 技術邊界

UI → application 命令／查詢 → domain 規則 → repository／原子工作單元 → IndexedDB。Excel 在 Worker 安全解析後呼叫同一領域驗證，不可直接寫表。Service Worker 快取程式，不保存使用者業務資料。

T02 才建立套件及鎖檔，屆時確認版本、授權、安全公告與瀏覽器能力。精確數學採 BigInt 定點／分數，邊界轉十進位字串。沒有執行期 CDN。

## 風險及未定事項

商業參數（虧損、免費、管理費、補款）保持未設定，不阻止保存有效交易、人工決定或結案。無法試算不代表金額零。

發布前實測 iOS／Android、Excel／LibreOffice、500 SKU／10,000 交易／20 成員；這是暫定測試量，不是保證或硬上限。檔案大小及解壓限制以實測設定且需在解析前檢查。GitHub Pages 免費資格、裝置能力及備份去向另驗證。
