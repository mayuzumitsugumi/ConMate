# 已納入路線圖：個人 GitHub 雲端備份（選配）

狀態：已確認產品方向，尚未實作。依使用者要求新增；不代表目前已有 GitHub 登入、上傳或還原功能。

## 定位與邊界

使用者可選擇連接自己的 GitHub 帳號，授權指定的私有 repository，將單一工作區專案檔存入自己的空間。這是備份與跨裝置交接，不是即時多人同步。

- 基本功能仍免帳號、離線優先，本機儲存與手動下載持續可用。
- GitHub 帳號只用於選配備份授權，不建立 ConMate 帳號或管理權限系統。
- 不把使用者資料存到 ConMate 公開網站 repository，也不以公開資料庫代管。
- 一個工作區仍是一份 XLSX，建議路徑 `conmate/workspaces/<workspaceId>/project.xlsx`。版本利用 GitHub commit 歷史，不按功能拆檔。
- 使用者明確選擇 repository、分支與工作區後才讀寫。第一版預設只接受私有 repository，不因錯誤自動改成公開或建立新 repository。
- 首版只有手動「備份到 GitHub」「從 GitHub 還原」與斷開連線。排程、自動背景備份、其他雲端供應商及同步留待後續。

GitHub Pages只提供網站檔案，不能因為使用者在另一分頁登入GitHub就取得存取權。自動備份須經另外授權與GitHub API；私有資料repository不需要啟用Pages。

## 頁面與主要流程

「專案檔與備份」增加選配「個人雲端備份」區；未連線時不打斷商品建檔，不反覆要求登入。

1. 連接GitHub：清楚說明將授權哪個儲存庫及用途，可取消。
2. 選擇自己的私有repository與分支；顯示目前帳號、工作區、目的路徑。
3. 備份：先產生一致修訂的專案檔，檢查遠端版本，再確認提交。
4. 成功後顯示確實完成的備份時間、來源修訂與遠端commit；失敗保留本機資料。
5. 還原：先下載到隔離暫存區，完整驗證、顯示工作區與修訂差異，再由使用者確認原子提交。
6. 換裝置：A停止操作並完成備份，B還原核對後接手；A仍可能繼續修改，介面必須說明這不是裝置鎖或同步。
7. 斷開：移除本機連線／授權狀態，不刪本機資料或遠端專案檔，另提供到GitHub撤銷授權的說明。

分開顯示「本機已儲存」「已發起下載」「GitHub備份成功」。連線成功不等於備份成功；若備份期間又新增資料，須顯示本機仍有未備份變更。

## 版本與衝突

- 每次備份保留workspaceId、格式版本、資料修訂與完整性資訊；既有穩定ID不可改寫。
- 更新同一路徑前檢查遠端blob SHA，提交時帶入已讀SHA；若變更或衝突則停止，不強制覆蓋。
- 相同檔案來自不同工作區、不同裝置分歧或未知格式時，不自動合併或以裝置時間判斷哪份較新。
- 衝突時提供查看摘要、先下載遠端檔、保留本機另存副本或重新選擇還原來源；不偷偷選邊。
- 還原前提供本機外部備份及還原點；取消、解析錯誤、斷網或寫入失敗不破壞原工作區。
- 遠端檔案與一般上傳檔同樣視為不可信輸入，不能繞過檔案安全、大小、公式、型別、關聯與重算檢查。

## 授權技術前置驗證

2026-11-03 已完成[授權可行性研究](github-backup-feasibility.md)：標準網頁 OAuth code 交換仍需 secret；PKCE 不自動移除此要求。純靜態可先驗證使用者自行建立的限定私有 repository fine-grained PAT、僅記憶體保存模式。此為技術候選，尚未提供線上連接或請求使用者憑證。


目前GitHub Pages純靜態與無後端的限制仍生效。實作前先驗證官方授權流程是否能在目標瀏覽器安全完成，尤其登入回呼、token交換、CORS與撤銷。

- 公開前端、repository、Service Worker及專案檔不得放client secret或共用寫入token。
- 最小化至使用者指定repository的必要Contents讀寫權限，不要求工作流程、組織或其他repository管理權限。
- 存取token不寫入匯出檔、錯誤報告、網址、日誌或預設的localStorage／IndexedDB；首版以工作階段記憶體保存，持久登入需另做安全設計。
- 若純靜態「登入即授權」無法安全完成，不自行加後端或要求大家共享token。提出可行替代（例如由使用者建立限定權限的授權）及取捨，再確認操作方式。
- 若最終需要額外服務，須另行確認成本、資料接觸範圍與原架構限制；不能因為納入本規劃就視為已授權引入後端。

## 必過驗收

1. 未連GitHub或拒絕授權，離線建檔與手動匯出不受影響。
2. 登入成功但未授權repository，不顯示已備份，也不寫入任何檔案。
3. 只把指定工作區寫到使用者指定私有repository，不混入其他工作區或ConMate程式庫。
4. 一份檔案包含所有目前支援資料、穩定ID、自訂選項及封存內容。
5. 成功上傳後才更新備份狀態；備份期間本機再修改仍顯示未備份變更。
6. 斷網、token失效、權限不足、限流及API錯誤保留本機資料，可重新授權／重試。
7. 遠端SHA改變時拒絕覆蓋；兩裝置分歧不自動合併。
8. 新裝置還原後商品、定義、型別、ID及修訂一致；來源較新版本安全拒絕而不清資料。
9. 損壞、超限、含公式或異常關聯的遠端檔案不能繞過驗證。
10. 使用者取消還原或本機提交失敗，原工作區完整保留。
11. token不出現在公開程式、匯出檔、儲存資料、網址、錯誤報告或日誌。
12. 斷開連線不刪使用者本機／遠端資料；可在GitHub撤銷授權。
