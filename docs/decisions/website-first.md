# 決策更新：網站先建檔、一個工作區一份檔案

2026-11-02；取代早期「使用者先填66張表」的入門流程。先前模型及財務規則仍作後續業務實作依據，但不能當作必填畫面。

## 入門流程

建立工作區 → 網站商品建檔 → 有需要才加標記／欄位 → 匯出一份XLSX。使用者不用填正式ID、new:或表格參照。只有商品名稱必填；創作者、企劃、周邊種類、規格及柄圖可補齊。未指定關聯是未指定，不是零成本或已完成財務設定。

周邊種類是自由文字，不以固定下拉限制創作。創作者及企劃已有資料時可選既有對象，或輸入新名稱。所有內部ID由系統產生。

## 標記與自訂欄位

- 標記描述用途，例如新商品、限定販售、清倉、再販、預購、親簽；建議標記需使用者主動加入，不自動改售價或觸發預購流程。
- 自訂欄位限商品額外資料：文字、數字、單選、多選、是／否、日期。不可作為自動財務公式或庫存來源。
- 定義及選項有穩定ID，改名稱不改已選關聯。既有欄位不能直接換型別；以封存代替刪除，提供恢復入口。
- 布林值區分未指定、是、否；數字0及false都保留。自訂數字是一般附加資料，顯示General；財務精確數學仍須專用模組。
- 設定依工作區隔離，不複製到別人的資料。

## 本機儲存與安全提交

沿用原本的conmate-workspaces-v1資料庫名稱，Dexie version2新增catalogs表，不刪除原工作區。每個工作區一筆版本化建檔資料集，包含產品及其參與方／企劃／種類／規格／系列／圖樣關聯。商品實體ID對應後續SKU；目前尚無出入庫或財務紀錄。

所有修改經repository transaction及expectedRevision檢查，失敗不提交計數器或部分新資料。其他畫面修改後拒絕過期寫入。封存保留歷史值，選項ID不得跨欄或跨工作區。

## 網站專案檔2.x

此為新的「ConMate網站專案」profile（v0.2發布2.0.0；v0.3增加企劃／場次日常表，發布2.1.0），與舊版完整模板1.0.0不同，不將兩者互相冒充。整份工作區只下載一檔：

| 工作表 | 出現條件與用途 |
| --- | --- |
| 00_專案說明 | 永遠出現，說明資料範圍與限制 |
| 01_商品 | 有商品時出現，列出名稱、創作者、企劃、自由種類、規格、圖樣、標記、備註、狀態與啟用的自訂欄 |
| 02_自訂設定 | 有標記或自訂欄位時出現，含封存設定 |
| 03_企劃 | 有企劃時出現，含說明、參場清單及封存狀態 |
| 04_場次 | 有場次時出現，含日期、地點、參加企劃及封存狀態 |
| 05_庫存、06_庫存異動 | 庫位餘額與完整異動紀錄 |
| 07_通販對照、08_異動類型 | 手動通販快照與自訂類型 |
| 09_銷售交易、10_銷售明細 | 收款、找零、實際SKU與退款回庫鏈 |
| 11_批次成本 | 明確輸入的成本及重算結果，空白保留未知 |
| 12_代墊本金、13_本金還款 | 本金與償還、沖銷及作廢歷史 |
| _ConMate資料 | 單一隱藏技術表，保存整份資料集，包括未顯示、封存、穩定ID及精確型別 |

空工作區只有說明與技術資料；沒有使用的成本、代墊、抽選等功能不輸出空表。未來模組實作後沿同一檔案擴充，不拆成每功能一個檔案。

隱藏表不是加密，可由使用者取消隱藏。UTF-8 JSON以12000-byte切片編為Base64（每片16000字元），避免試算表XML跨字元邊界或儲存格長度造成損毀。payloadByteLength與SHA-256核對完整性；這不是防竄改簽章或授權機制。

v0.4.0起提供網站專案檔的安全檢查及還原。v0.5.0增加庫存異動；v0.6.0增加人工維護的通販可售數量對照，v0.7.0加入自訂庫存異動類型，格式升至2.4.0/schema6；v0.8.0加入實際商品交易與基礎成本／代墊，格式升至2.5.0/schema7。通販數字是使用者核對快照，未串接商店API，不自動預留或扣除實物。還原支援2.1.0至2.5.0並補齊新增資料，不推算舊數量。檔案先在隔離解析區驗證，使用者確認後才原子新增工作區；同ID拒絕覆蓋。日常表修改不會被匯入採用；不支援舊模板1.0.0匯入。

v0.3以Dexie version3升級網站資料schema2至schema3，保留全部既有建檔資料並補齊企劃狀態、events及projectEvents。

## 雲端備份選配

v0.16.0已實作[個人GitHub雲端備份](personal-cloud-backup.md)：使用者自行設定專用私有repository與限定範圍的fine-grained PAT，提供手動備份、版本核對及安全還原。權杖僅在當前頁面記憶體保存，這不是OAuth登入；Google／Microsoft雲端授權尚未接入。基本功能仍免帳號／離線，也不把資料存到ConMate公開網站repository。

## 驗收

網站完成新增／編輯／封存恢復、一般與自訂類型資料、重開持續保存、工作區隔離、過期修訂、v1資料庫升級、隱藏完整資料核對、UTF-8及emoji、公式樣貌文字、數字0／false、離線Worker匯出。實體手機、Excel／LibreOffice的人工相容性仍需持續驗證。

## 自訂庫存異動類型

使用者可自訂名稱，建立時選增加、減少或移動庫存；此方向建立後不可修改。舊異動名稱、數量與ID不變，新異動保存當時類型名稱。類型封存不刪歷史，新增紀錄不能選封存類型。庫存類型不代替銷售及財務紀錄，不從名稱推測收入或成本。

## 販售與基礎財務（v0.8.0）

- 成交需指定實際SKU、出貨庫位、數量、整元單價及實際收到金額。抽選僅記錄已知交付款式，不由系統抽取。指定與抽選共用庫存。
- 營收只來自已提交交易；草稿不扣庫、不保留、不認列。成交與全部出庫同一原子提交，失敗全部回滾；operationId防重送。
- 此版退款只支援「整筆全額退款且全部商品回到原庫位」。新增反向分錄並保留原交易，不能直接從庫存頁沖銷販售分錄。部分退款、換貨及損壞退貨後續開發。
- 批次成本不建立庫存或付款；未知費用保留null，無費用須明填0。柄圖費為使用者指定分配額，並非此版自動分攤。所有金額以安全整數TWD輸入，精確分數計算單件成本後才取四位顯示。
- 代墊只登記已實付且約定可追收本金；還款不視為營收、費用或利潤。更正以沖銷還款、作廢無有效還款的本金處理。
- 成本表的付款者／負擔者為註記，不自動建立欠款；分潤尚無規則時顯示尚無法試算，使用者自行決定結案。
