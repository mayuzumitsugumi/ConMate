# 雙入口與活動交接契約

ConMate 以同一份資料及領域規則提供「創作管理」和「活動工作台」。前者處理持續企劃、商品及財務；後者處理兩週內、交付範圍明確的短期活動。兩個入口不是帳號權限。完整工作區可使用兩個入口，活動檔則獨立保存交付範圍。

## 檔案與交付

- 網站完整備份：schema17／Dexie18／格式2.15，包含交接基準、本機活動進度、合回歷史及其他完整資料；舊版本安全升級。
- 活動進行／結案檔：獨立 `ConMate活動專案 1.0.0` XLSX，不能當成完整工作區覆蓋匯入。
- 同活動可拆多份，每份有穩定識別、來源、版本與數量；原子調撥到獨立交接庫位，不增加實物總量。一般創作管理命令不能在合回前改動該庫位。
- 只帶選取商品、必要主檔、該活動、方案及數量。排除未選商品／企劃、其他庫位、私人備註、自訂資料及其他活動歷史。隱藏技術表也使用同一範圍，隱藏不是保密。
- 可明確勾選相關財務參考摘要；它是唯讀、限範圍的成本／代墊／分配等資料，不是整份私人財務或完整歷史編輯權。
- 活動用合成初始入庫對應原實物批次，避免洩漏原庫存歷史。交付時的成本版本識別保存在創作管理，不在未授權的活動檔公開成本。

## 工作台與續作

可販售、退款、無料、損耗、盤點、記錄活動支出／交款，以及追加有來源的更正。既有交付量與製作成本不可直接改寫；價格與展示名稱變更保存修訂原因，舊成交快照保留。新增品項需一次填實際帶入量與來源，追加同款亦另建品項。

活動現金更正以新紀錄指定被更正項目，金額代表更正後金額，不把原金額與修正金額重複相加。不由名稱推算收入、欠款、代墊或分潤，網站不實際轉帳。

購物車草稿可保存進活動檔，草稿不保留庫存。活動進行檔可反覆匯出與匯入續作，同一份同時只由一人負責。版本鏈只接受相同內容或已知版本後裔；分歧不以較大修訂或較晚時間盲目覆蓋。無後端不能提供跨裝置鎖或即時同步。

超過兩週提示使用創作管理處理長期活動，但不阻止既有檔案讀取、盤點或結案。

## 結案與合回

必須逐項填實點數量，並成交或捨棄草稿，才可結案。差異需說明，可以待查；不要求歸零或清款。結案檔不可重開，所有工作台寫入命令都拒絕；創作管理另加更正，不改寫原報告。

未結案活動不能合回。結案檔先驗證交接基準與範圍、顯示交易／費用／庫存異動及差異，活動新增商品須逐項確認建立或對應，不能以名稱猜測。

確認後僅原子新增交接範圍的異動，初始交付不重複入庫，其他企劃與活動期間再製保持原樣。合回保存本機復原點。同一內容重匯不重複記帳；同交接份不同結案、來源被改動或紀錄識別衝突時拒絕合併。不同份可分別合回，列表顯示各份狀態。

剩餘實物留在交接庫位，等確實收到後才確認退回一般庫位。實點與帳面有差異時，先以有原因的創作管理調整處理，再確認退回。合回不是實物已交還。

批次成本沿用交付時已存在的成本版本，不用後來的成本改動回填活動銷售；未提供成本仍顯示未知。活動財務不自動抵付代墊或重複扣分潤。

## 限制與驗證

Checksum 是完整性核對，不是數位簽章或遠端身分證明。離線副本仍可能分歧，因此需保留來源及版本核對。活動不是完整帳務權限系統。

驗收包括雙入口、分份數量守恆、私人資料排除（含隱藏表）、跨乾淨裝置續作、改價／展示修訂、新品一次帶入、盤差結案、永久唯讀、局部冪等合回、保留原工作區持續工作、分開實物退回，以及舊備份／本機復原點相容。
