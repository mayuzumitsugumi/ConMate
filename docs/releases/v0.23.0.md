# v0.23.0：特殊單件追蹤

親簽、編號品等實物可在已知入庫批次中逐件登記辨識標記，數量不會因登記而增加。同一商品可同時包含一般數量與已標記實物，網站不推算舊銷售的實物身份。

- 每件實物由系統產生穩定 ID，使用者填寫實物上可辨識的標記；重複標記或超過批次現存數量會拒絕。
- 販售、移動、無料與損耗需明確選擇標記，數量與所選件數一致；一般數量不能挪用已標記實物，同一行不能混合兩種方式。
- 單件指定出貨保留原來源批次。可售及損壞退貨都要選原成交實物，不能重複退回；成本核對沿用原成交成本版本。
- 交接檔只帶所選單件；合回後保留原 ID，其他單件與未交付資料不會帶出。活動端新增商品仍採一般數量，不能補造來源單件。
- 活動結案逐件確認剩餘實物，可將差異標記待查；實物退回前需先在創作管理明確處理差異。正式盤點的單件差異不自動推定是哪件遺失。
- 專用預留仍按商品／方案數量核對，成交同時驗證配額與實物位置。草稿保存所選標記，但不占用庫存；提交時再次驗證。
- 完整備份升至 schema19／Dexie20／Excel2.17，加入特殊單件工作表。舊備份、活動檔與本機復原點補空清單，不猜測歷史身份。

目前不提供實體標籤印製、條碼掃描、未知舊來源的身份回填或活動端新增特殊單件。標記需使用者確實貼附／核對，軟體無法辨識實物真偽。

下一階段依路線圖為換購差額及現場效率，本版不包含。

驗證：292 項單元測試、12 項契約檢查、型別檢查、建置及 52 項桌面／手機瀏覽器測試通過。新增測試包括登記不增量、未選不能扣單件、原實物精確退貨、任意來源成本、舊資料升級、草稿保存標記，以及實際斷網的活動交付／盤點／結案／合回／退回整個流程。
