# v0.24.0：換購與實際差額

創作管理的販售頁及活動工作台新增「換購與差額」。保留原交易，選擇退回商品與折抵額，再加入新交付商品；使用者明確確認實際補收／退還差額後，原退貨與新出貨一起提交。

- 差額＝新商品成交總額－原交易折抵額。正數補收、負數退還、0表示沒有收退；輸入的實際差額必須吻合，不自行推定已付款。
- 原交易的換購折抵另標記為折抵，不冒充已付一筆完整現金退款。新交易記錄折抵額及真正補收／退還，原成交與退款／折抵仍保留以便核對營收。
- 所有退貨、新出貨、預留配額及批次異動原子完成；庫存不足、價格過期或資料錯誤時不留半筆。相同操作重送不重複記帳。
- 部分退貨、損壞退回、先前已退款及特殊單件均沿用既有規則；單件須指定原實物，新出貨也明確選實物。可售回庫與損壞紀錄分開。
- 換購子交易不能直接取消或改寫；之後可另加退款／退貨更正。網站不會實際收款、退款或轉帳。
- 活動檔保留完整換購來源，結案後唯讀；合回以原識別碼防重複並對應活動新增商品及方案。

資料升至 schema20／Dexie21，完整專案格式2.18。舊資料補空換購清單，不把舊退款或獨立換貨交易自動改為差額交易。所有已開放資料仍保存在同一備份中。

下一階段為按活動、商品、企劃及創作者的報表與核對；條碼、圖片、外部編輯匯入、寄賣／預售仍待後續。

驗證：312 項單元測試、12 項契約檢查、型別檢查與建置，以及 56 項桌面／手機瀏覽器測試。新增案例涵蓋正負零差額、部分退款後換購、原子失敗回滾、重送防護、特殊單件、預留、未知成本、版本過期、異常來源拒絕、舊活動重匯及完整專案往返；活動流程以實際斷網完成換購、結案、檔案回傳與合回。
