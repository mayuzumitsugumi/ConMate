# v0.28.0：預售、分次收款與分批交付

創作管理新增預售作業，串起訂單、訂金／尾款、實際交付、取消與退款。這是本機紀錄工具，不會代為收款、寄送或決定訂金條款。

- 訂單保留確認時的商品名稱、數量及單價。建立訂單可沒有現貨，不增加庫存、不自動預留，也不先產生已交付營收。
- 收到訂金或尾款後，逐次登記實際金額、時間及收款對象；未指定對象保留未知，不由商品擁有者推定。
- 交付可分批進行，每次僅從一般庫位扣除實際交付量，保留FIFO批次或指定單件。其他方案的預留數量、活動交接與寄賣庫位不可挪用。
- 未收齊款但確實已交付時，需明確確認並註明原因；系統保留待收差額，不補造收款，也不自行決定信用交易條款。
- 只能取消尚未交付的數量；取消會減少訂單承諾金額，但不代表款項已退還。已交付商品另循原交易退貨，不直接刪除出貨歷史。
- 可售與不可售退貨保留原成交商品／單件及原成本依據；退貨折抵是營收與訂單金額更正，實際退現金另行登記，兩者不重複算現金。
- 實際退款不能超過仍有效的已收款；若退款後仍有待收差額，需明確確認。收款誤記以沖銷更正，不把沖銷當成實際現金支出。
- 顯示原訂購、取消、已交付、待交付、已收、已退及待收／多收；可保留未完成事項結束訂單，必要時明確重新開啟，歷史保留。
- 營運報表以實際交付核對商品營收與成本；顧客現金表另列預售實收／實退，不把交付當成第二次收款。誤記收款的更正會排除無效原收款，而不是另加一筆假退款。

完整備份升至schema22／Dexie23／Excel2.20。舊備份、活動進行／結案檔及本機復原點維持相容；預售顧客代稱與訂單紀錄不加入無關活動交接檔，也不透過主資料範本修改。

## 範圍限制

- 首版在創作管理登記一般庫位的實際交付，尚不把顧客預售訂單交給活動工作台或寄賣店履約。
- 訂單不自動占用未來製作量、保證供貨、沒收訂金或建立收款連結。
- 退貨不自動重新建立一筆待交付商品；後續再購或更改約定需另行明確處理。
- 金額與時間由使用者核對登記，不提供線上金流、物流平台或顧客登入。
- 顧客只需可辨識代稱；本機與Excel備份不是加密保管服務，請避免填入不必要的個資。
- 真實手機操作與使用者自己的試算表／私人雲端驗收仍由使用者確認；自動化測試不冒稱實機驗收完成。
