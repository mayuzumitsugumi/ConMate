# v0.29.0：第一版驗收候選版

補齊商品辨識與日常編輯效率；雲端 OAuth、多人同步、相機掃碼與標籤列印延後。本版是供實機驗收的候選版，尚非 v1.0 正式發布。

## 新功能

- 商品可填選用條碼，最多80個可列印ASCII字元，不含空白；以文字保存前導零。系統商品編號也可查找。不同商品可有相同碼，查找時明確選擇，不依名稱或第一個匹配自動成交。
- 創作管理的攤位販售及活動工作台提供條碼輸入，支援鍵盤式掃碼槍或手動輸入。Enter只查找，選取商品後仍需確認方案、數量、單價及收款；不替使用者抽選實際款式。
- 商品可從本機PNG／JPEG／WebP建立最長邊160px縮圖。原檔最多5 MiB、2,400萬像素；重編碼後每張data URL最多24,000字元，工作區總計最多4,000,000字元。原始圖片不保留，請自行保存原檔。SVG、遠端URL及嵌入執行物件不採用。
- 圖片只存目前裝置及使用者匯出的檔案，不使用外部圖床。活動交接只攜帶本份交付商品的縮圖與條碼，未交付商品及私人備註不帶出。
- 商品可勾選1至100項，預覽統一的備註修改，再一次提交；可明確清空。過期預覽拒絕提交，未選取商品、成交快照、庫存及帳務不受影響。其他欄位可逐項修改或用專用主資料匯入，不提供危險的全表直接改寫。

## 備份與相容

- 資料schema23／Dexie24、完整專案格式2.21.0、活動檔格式1.1.0。舊完整備份及活動1.0檔仍可升級讀取；新版完整檔與活動1.1檔不交給舊版程式處理，避免靜默丟失圖片與條碼。
- 完整備份內保留縮圖、條碼及原有資料。日常閱讀表不是可直接編輯還原入口；主資料編輯匯入維持既有範圍，不抹除圖片與條碼。
- 匯出前檢查與匯入相同的檔案容器限制：壓縮10 MiB、展開30 MiB。超限時不建立下載檔、不標記備份完成，保留本機資料並顯示原因；不放寬解壓安全上限。
- 縮圖總量限制不是備份必定可容納的保證：交易、活動快照、備註也占空間。請定期實際匯出並在練習環境驗證還原，不要刪除正式資料來解決備份問題。

## 容量驗證與限制

自動容量案例使用500商品、20創作者，由有效API交易範本成對展開虛構交易／出庫紀錄；並非實測手機連續操作一萬次。

- 1,000筆交易：完整XLSX檢查及IndexedDB還原通過。
- 10,000筆交易：資料驗證、商品／創作者／日期報表與現金及庫存守恆通過，但XLSX展開約42 MB，超過30 MiB，必須拒絕匯出／匯入，**不能宣稱一萬筆可完整備份還原**。
- 這些是開發環境測試，不是公開性能保證，也不涵蓋500張最大縮圖。大量歷史資料的壓縮備份格式或容量擴充另待後續設計，不能靠調大解壓限制處理。

## 驗收與發布

本機自動檢查：393項單元／整合測試、12項契約檢查、66項桌面／手機瀏覽器流程測試、型別檢查及正式建置通過。遠端檢查與部署結果以同一提交的CI為準。Android、iOS、主畫面模式、實際掃碼槍、Excel／LibreOffice重存與私人GitHub備份交給使用者驗證；見[第一版驗收清單](../first-release-checklist.md)。

原v0.28的單次Pages卡住修復已移除，工作流程回到正常檢查與發布，不會在日後發版取消舊部署。
